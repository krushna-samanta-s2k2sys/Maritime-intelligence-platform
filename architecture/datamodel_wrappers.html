Special Logic & Gotchas
Coordinate swap for AIS_ROUTES: GeoJSON stores coordinates as [longitude, latitude] but Leaflet expects [latitude, longitude]. mapData.js converts:
routeData.features.map(f => f.geometry.coordinates.map(([lon,lat]) => [lat,lon]))
VESSEL_GEO properties contain dual keys: Both short keys (nm/ty/st/sog for GisAis sidebar) AND long keys (name/type/status/speed for DashboardGrid popup and vesselColor()).
PORT_GEO type derivation from global_rank: rank ≤ 3 → 'mega', rank ≤ 7 → 'major', else 'regional'. Also derives calls from throughput_teu for popup display.
choke_points.json uses latitude/longitude (not lat/lon): mapData.js reads cp.latitude, cp.longitude explicitly.
gis_companies.json uses hq_lat/hq_lon: mapData.js reads c.hq_lat, c.hq_lon (not the generic lat/lon pattern).

COL_ID_MAP bridges attribute IDs to short column IDs: attributeRegistry.js maintains a COL_ID_MAP that translates af-* attribute IDs (e.g. 'af-dwt') to the short column IDs stored in personas.json vessel_columns arrays (e.g. 'dwt'). This bridge is required because personas store column preferences using short IDs but the attribute tree uses prefixed IDs.

5 system personas: Ship Owner, Charterer, Compliance Officer, Port Agent, Analyst. Each persona defines: vessel_columns[] (short col IDs matching COL_ID_MAP), attr_sections[] (which sections show in vessel detail), and dashboard_cards[] with card_id/width pairs. dashboardCards are mapped from card_id/width pairs defined in personas.json.
