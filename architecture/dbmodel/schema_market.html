Market & Geo Schemas

The market schema stores freight indices (BDI, BDTI, BCTI, BLNG), route benchmark values, spot fixture reports, time-charter contracts and vessel valuations — all sourced from Clarksons, Baltic Exchange and broker networks. The geo schema provides quasi-static GIS reference data: maritime chokepoints and PSC MOU patrol zone polygons.

9 tables total market: fixtures, TC contracts, benchmarks, valuations geo: PostGIS Point + Polygon geometries GENERATED lat/lon from geom 2 utility functions in registry schema

geo Schema Maritime chokepoints & MOU patrol zones

geo.choke_point

Purpose: Quasi-static reference table for the world's major maritime chokepoints. Mirrors choke_points.json. GENERATED ALWAYS AS columns extract lat/lon from the PostGIS point geometry. Not EAV — geometry changes are rare and updated directly. Seeded with 8–12 chokepoints: Suez, Hormuz, Malacca, Bab-el-Mandeb, Panama, Turkish Straits, Cape of Good Hope, Danish Straits.

Purpose: PSC MOU patrol zone polygons for map overlay rendering. Mirrors mou_zones.json. The "bounds" array in JSON (array of [lat,lon] pairs) is converted to a PostGIS Polygon geometry on ingest. Utility Functions (registry schema)

registry.attr_at(p_entity_schema, p_entity_id, p_attr_key, p_valid_at, p_sys_at)

-- Point-in-time attribute lookup for ANY entity following the standardized schema template.
-- Returns the highest-confidence APPROVED value for the given entity + attribute at a historical moment.

Example usage:
SELECT * FROM registry.attr_at(
    'vessel',      -- entity schema: 'vessel' | 'port' | 'company'
    '9234567',     -- entity ID (imo_number / unlocode / company_id)
    'deadweight',   -- attr_key from registry.attribute_def
    '2024-06-01',   -- p_valid_at: real-world time to query
    NOW()            -- p_sys_at: system time (for bi-temporal as-recorded query)
);

Returns: value_text, value_numeric, value_boolean, value_date, value_json,
         confidence, source_code, valid_from, sys_from

registry.refresh_all_current_views()

-- Call after each ingest run to refresh all current-state materialized views.
-- CONCURRENTLY = zero-downtime refresh (reads continue during refresh).

Refreshes (in order):
  1. vessel.latest_position   — deduplicated latest AIS position per vessel
  2. vessel.v_current         — full attribute pivot for all vessels
  3. port.v_current           — full attribute pivot for all ports
  4. company.v_current        — full attribute pivot for all companies

geo.choke_point and geo.mou_zone are base tables — no refresh needed.
